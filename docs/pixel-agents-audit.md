## DevDay extension connection

The presentation centers on the **conversation aquarium panel**, **custom `.reef` file viewer with replay/scrubbing**, and **Model–App Context sharing of one deliberately selected event**. Native hooks supply local activity; the Codex SDK supplies richer launched-run recordings. Neither the SDK nor tunnel plumbing is presented as the new extension capability.

Use the supported [plugin extensions](https://developers.openai.com/plugins/build/extensions), [plugin packaging](https://developers.openai.com/plugins/build/plugins), and [Codex hooks](https://learn.chatgpt.com/docs/hooks) contracts. Hook trust is separate from plugin installation. Hosted search and some specialized tools are outside documented hook coverage. There is no established API here for automatically binding the panel to the current chat, so the viewer provides explicit session selection.

## Remaining qualification

See [plugin integration](plugin.md) for installed-runtime and actual-host status. Browser/AppBridge tests do not prove native panel rendering, file dispatch, or context sharing into the actual conversation. Cross-platform installation, long-running retention behavior, and abrupt host crashes require further qualification.

## Installed-host compatibility finding

Real testing found that Codex 0.161.0 loads portable MCP tools but deliberately skips portable plugin hooks. A separate generated legacy package is required for this installed runtime. The portable extension package remains available. This is why current documentation alone was insufficient: the actual `/hooks` inventory initially reported zero hooks, then ten after compatibility installation. See the [version-matched loader](https://github.com/openai/codex/blob/rust-v0.161.0/codex-rs/core-plugins/src/loader.rs#L951).
